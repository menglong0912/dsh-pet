# 历练任务书：三王传承试点（2026-10-27）

给开发 agent 的任务书：每个任务写清现状、改法、测试和验收，主会话负责核验。设计依据和取舍理由见同目录的 `cultivation-adventure-design.md`（下称「设计」），两边不一致时以本文为准。

- **基线**：`custom` 分支 `a062d8c`（修炼 X14）；X14 落地时 `npm test` 1326 个全过，typecheck / lint / prettier 干净。开工前先自己跑一遍确认。
- **路径**：下文代码路径都相对包目录 `dsh-pet/`；仓库根是它的上一级。
- **素材**：由主会话用即梦生成（YA），名字见 §2.3。开发 agent 不生成、不改素材；素材晚到不挡开发，缺了的一律走兜底（§2.1）。
- **编号**：和设计 §11 的 Y0–Y8 不一样，以本文为准。设计的托管、日常奇遇等放到试点之后（§0）。

## 2. 通用约定

`cultivation-roadmap.md` §2 全部照用（它又引用 `standalone-roadmap.md` 的 §2.1、§2.3、§2.5）。本节只写新增。

### 2.1 新增约定

- **`features.ts` 已经 2 758 行**：秘境的流程放进 `adventure-flow.ts`（构造时注入依赖，同 `BattleShow` 的写法），`features.ts` 只做接线，新增不超过 150 行。
- **先记账再演出**：主人每做一个决定，先由纯逻辑算出结果、写进存档，再演。演到一半退出 app，重开时这一步已经算完，直接到下一个决定；不会重算、不会换结果。
- **种子**：一趟的种子在进秘境时定下、存进存档。每个节点的随机数都从它派生：`种子 + 层 + 节点 + 第几轮`。「第几轮」是春秋蝉倒带用的：倒回去以后同一层要重新掷，不然照样再输一次。
- **素材缺了不报错**，按下面兜底，播之前不查文件在不在：

  | 缺的               | 兜底                                                       |
  | ------------------ | ---------------------------------------------------------- |
  | 对手的某段动作     | 立绘加 CSS 动作（扑、抖一下闪红、侧移、倾倒淡出）          |
  | 对手立绘           | 一个带名字的剪影色块（只为不崩，真机前素材必须齐）         |
  | 节点插画、奇遇插画 | 显示这个秘境的地图                                         |
  | 过场视频           | 封面淡入，配开场文字                                       |
  | 宠物的秘境动作     | 那一下没动画，气泡照出（同 `cultivation-roadmap.md` §2.3） |

- **对手不进图鉴和名帖**：对手招式和一转蛊另开一张表（Y0），不进 `WEAPON_IDS` / `SKILL_IDS`，不会掉落，切磋的名帖不认它们。所以 `BATTLE_VERSION` 不升（Y0 有快照测试兜住）。
- **文风**（设计 §4.14）：每个场景两三行短句；对白用「」；地点写成「三叉山 · 犬王传承」；原著原话（「三王传承，今日开启，正魔不论，留待有缘。」）放在最显眼的位置。画风是 Q 版，不写血腥。

### 2.2 不能放宽的边界

1. **全在本机算**：秘境、对手、战利品都不上网。多人的口子只是数据结构，试点不发任何包。
2. **输了不受罚**：输了只是这一趟到此为止，已经拿到的照拿；不扣修为、不丢东西。
3. **收益不封顶，但赶路不能跳**：每一步赶路 15 秒，快进只压缩战斗（设计 §7.2）。赶路由存档里的「这一步什么时候走完」管着：关小窗、退出重开都跳不过去。
4. **模型调用**：每趟 +1（走完时一句游记式总结），其余台词全用模板。

## 3. 任务详情

### Y0 秘境纯逻辑：引擎补丁、通用跑图、三王传承数据

**目标**：给定存档里的一趟状态和主人的一个决定，算出下一个状态和这一步要演什么。不碰 Electron、不读写文件、不读时钟（`now` 由参数传入）、不调模型。

#### 引擎补丁（`battle.ts`）

1. **开场气血**：`Fighter` 加可选 `hpNow?: number`，开打时的气血，不给就是满血，夹在 1 到 `hp` 之间。`start` 事件的 `hp` 按它。
2. **招式表 `MOVES`**（一转蛊和对手招式，新）：
   - `MoveDef` 的结算字段和 `WeaponDef` 一样（`min`、`max`、`hits`、`comboBonus`、`skipChance`、`skipCause`、`mustHit`、`ranged`、`heavy`），另加 `uses?: number`（一场最多用几次）；
   - `Fighter` 加可选 `moves?: MoveId[]`，以及 `pack?: number`（驭犬蛊的狗数，见下表）；
   - `Action` 加 `{ kind: 'move'; move: MoveId }`，`hit` / `combo` 事件加可选 `move`；
   - `autoController`：有次数限制的招每次 35% 用，用完为止；其余的招和法宝放在一起随机挑。只有招、没有法宝时（对手、压境入内的宠物），驭犬蛊每次都用，别的招 80% 用、20% 空手。

3. **加持修正**：`Fighter` 加可选 `mods?: { dodge?: number; desperate?: number }`：闪避率加成（闪避上限照旧），气血低于三成时的伤害倍率。
4. **替挡**：`Fighter` 加可选 `guard?: { by: string; times: number }`：挨打的前 `times` 下整下被别人挡掉，新事件 `{ kind: 'guard'; actor（挨打方）; by; hp }`。只用在定仙游结局（白凝冰被逼着挡在前面）。
5. **不变式**：不带这些新字段的 `Fighter`，`fight` 的事件序列和现在逐条一样，所以切磋两边照旧兼容，`BATTLE_VERSION` 不升，`visit.ts` 不动。
   - 改代码之前，先用固定种子跑 200 场随机配招的对局，把事件序列的 sha256 写进测试；改完必须对得上。

6. **解说**（`battle-lines.ts`）：每个招 2–3 句，`guard` 2 句，每句 40 字以内，例如「{a}放出一群狗扑上去，-{d}」「白凝冰挡在{b}前面，硬接了这一下」。
7. **演出先只要能编译**（`battle-show.ts`）：招式出手查不到演出表就按空手演；`guard` 只刷新气血、出台词。真正的演出在 Y2。

#### 通用跑图（`dungeon.ts`，新，配 `dungeon.test.ts`）

**秘境定义 `DungeonDef`**（纯数据，血色禁地以后照着加）：编号、名字、原著境界、5 层节点、对手名册、奇遇、加持池、文案，以及规则钩子（倒带、不能撤的层、结局怎么定）。三王传承特有的逻辑只写在它自己的数据文件和钩子里，通用跑图里不出现「春秋蝉」「白凝冰」这些名字。

**节点**（设计 §4.2，按场景换皮）：

| 种类       | 结算                                                                      |
| ---------- | ------------------------------------------------------------------------- |
| 小怪、精英 | 一场全自动战斗，气血接着上一场                                            |
| 宝箱       | 修为 +3–6，15% 破境丹；20% 是机关，按身法判定躲开，没躲开扣 15% 气血      |
| 灵泉       | 回 30% 气血                                                               |
| 奇遇       | 两三个选项；选项可以带判定（属性 + 难度，成功率显示在选项旁边）和出现条件 |
| 遗迹       | 加持三选一，只在这一趟有效                                                |
| 守护       | 先亮出对手的打法，主人挑最多 3 件法宝（不挑就全带），完整演出             |

**一趟的状态 `Run`**（导出 zod 的 `runSchema`，Y1 存档要用）：

```ts
{
  version: DUNGEON_VERSION,          // 1；秘境规则变了就 +1，旧版本的一趟按撤退结算
  dungeon: 'sanwang',
  nonces: string[],                  // 进秘境时的随机数，现在只有一份
  seed: string,                      // seedOf(nonces)
  suppressed: boolean,               // 压境入内
  mode: 'solo',
  leader: 'self',
  members: [{ id: 'self', name, hp, loot }],   // 现在只有自己
  layer: number, step: number,       // 第几层、这一层走到第几步（大殿有好几步）
  path: number[],                    // 每层选了哪个节点
  attempt: number,                   // 第几轮（春秋蝉倒带后 +1）
  blessings: BlessingId[],
  flags: Record<string, string | number | boolean>,   // 秘境自己的状态：三王的哪一王、驭犬蛊数、记得、识破……
  snapshot: Run 的一份拷贝（不含 snapshot 和 decisions）| null,   // 进这一层时存的，倒带用
  decisions: Decision[],             // 选路、选项、挑法宝，以及每场战斗里自己一方的每次出手
  readyAt: number,                   // 这一步的赶路什么时候走完；之前不收新的决定
  startedAt: number,
}
```

`loot` 是这一趟攒下的东西：`{ xp, pills, weapons, scrolls, titles }`，走完一并入账（Y1）。

**接口**：

- `startRun(def, { pet, stage, suppressed, nonce, now }): Run`：`pet` 是 `Cultivation.fighter()`，`stage` 是当前小境界。
- `choicesOf(def, run, pet): Choice[]`：现在能做的选择：下一层的节点、奇遇的选项（带成功率）、加持三张卡、守护前挑法宝、「催动春秋蝉」、撤退。
- `advance(def, run, pet, decision, now): { run, outcome }`：推进一步。`outcome` 写清这一步要演什么：赶路、战斗（双方 `Fighter`、事件序列、对手编号）、开箱、回血、奇遇结果、倒带、结束（原因和战利品）。`now < run.readyAt` 时拒绝。
- `settle(def, run, reason): Loot`：`reason` 是 `clear` / `lose` / `retreat` / `expired`。压境时修为 ×1.5，各秘境的修为一样（设计 §4.7）。
- `expired(run, now)`：进了 24 小时还没走完，按撤退结算。
- `autoDecide(def, run, pet): Decision`：托管的挑法（设计 §4.8），倒带一律用、大殿里一律识破加改炼定仙游。试点不接托管，模拟和测试要用。

**数值**：

### Y1 存档与结算

**目标**：一趟的状态存进 `cultivation.json`；走完时战利品一次入账，和修为写在同一次存盘里。

**存档**（`cultivation.ts`）：

- 加 `adventure: { run: Run | null, cleared: Record<秘境编号, { runs, bestLayer, bossWins, endings: string[], sealed }>, titles: string[] }`，各字段 zod `.default`，`version` 不升，旧档照常读得出来。`sealed` 是压境通关过（小窗上盖「原著印章」）。
- `today` 加 `dungeon`（`.default(0)`，今天走完了几趟，只给日记和设置页看，不封顶）。
- `run` 单独用 Y0 导出的 `runSchema` 校验，坏了不连累整个存档：
  - 版本对不上：按撤退结算，已经拿到的照拿；
  - 内容坏了、读不出来：丢掉这一趟并 warn；
  - 两种情况都不要把整个存档当坏档重建。

**接口**：

- `adventureRun(): Run | null`；
- `saveRun(now, run)`：每一步推进后写盘；
- `adventureDone(now, run, reason): CultivationEvent[]`，在一次存盘里做完下面这些：
  - 修为走 `addXp`，圆满了照旧不涨；
  - 破境丹进库存，库存满 9 颗时每颗多出来的换修为 +12；
  - 法宝去重后加进来；
  - 功法玉简：还有没学的招式，就挂一个二选一（复用 X4 的 `offer`）；只剩一门没学，直接领悟；已经有一个二选一挂着，或者全学会了，换成一颗破境丹；
  - 称号去重后加进来；
  - 更新 `cleared` 和 `today.dungeon`，`run` 清空。
- `tick` 里顺手检查 `expired`：进了 24 小时的一趟按撤退结算，发的事件和 `adventureDone` 一样。

**事件**：照现有的 `xp`、`drop`、`pill`、`offer`、`choose`，新加 `{ kind: 'title'; title }`。

**测试**：

- 旧档（没有 `adventure`）读得出来；
- 一趟走到一半重开 app，`run` 原样回来；
- 入账：修为、破境丹溢出换修为、法宝去重、玉简的三种情况、称号、`cleared`；
- 版本对不上的 `run` 按撤退结算，读不出来的 `run` 丢掉，修为、法宝这些都不受影响；

  - 拖出屏幕是松手时（`moved`）才拉回，拖的过程中不拦；
  - 走完一趟顺手刷新一次菜单，收掉「自动走」那一项；
  - 渡劫后的二选一还挂着、又正好在打历练的战斗时，修炼会暂时有 6 项，靠总数 20 的兜底截断。
- **菜单刷新的竞态**（主会话修）：开发 agent 跑全量时，Y3 的「关了小窗，菜单项回来」两次超时。它当成了老的不稳定测试，Y3 落地情况里主会话也猜错了。
  - 根因：`refreshMenu` 可以并发。每次先按当时的状态算菜单，再发 `/menu/item`，回来才记下 `menuLabels`。小窗刚关时，「小窗开着」那份可能后到宿主，菜单就停在旧状态；之后没有新变化，就不会再刷。
  - 修法：排队，上一次回来以后，下一次才按那时的状态重算再发。队列变量放在函数开头的状态区，避免初始化时还没走到声明就被调用。
  - 真机上表现是：关了小窗，心魔试炼偶尔要等下一次菜单变化才回来。
- **验证**：prettier（改动文件）、typecheck、lint 干净；全量连跑两次，都是 **1396/1396**。
